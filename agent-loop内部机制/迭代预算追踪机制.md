# 迭代预算追踪机制 —— 跨父Agent与子Agent

## 概述

Hermes Agent 使用**双重计数器**来追踪和控制每轮对话的 API 调用次数：

| 计数器 | 类型 | 语义 | 可否递减 |
|---|---|---|---|
| `api_call_count` | 局部 `int` 变量 | 展示用的"第N轮"序号 | 仅在重试场景递减 |
| `iteration_budget` | `IterationBudget` 对象 | 可退还的资源配额 | 退还即递减 |

**核心不变式**：`api_call_count >= iteration_budget.used`（永远成立）

---

## 核心数据结构

**文件**：[`agent/iteration_budget.py`](../../../hermes-agent-main/agent/iteration_budget.py)

```python
class IterationBudget:
    """Thread-safe iteration counter for an agent."""

    def __init__(self, max_total: int):
        self.max_total = max_total    # 预算上限
        self._used = 0                # 已消费次数
        self._lock = threading.Lock() # 线程安全锁

    def consume(self) -> bool:
        """消费一次迭代，达到上限返回 False"""
        with self._lock:
            if self._used >= self.max_total:
                return False
            self._used += 1
            return True

    def refund(self) -> None:
        """退还一次迭代（压缩重试、中断fallback等场景）"""
        with self._lock:
            if self._used > 0:
                self._used -= 1

    @property
    def remaining(self) -> int:
        with self._lock:
            return max(0, self.max_total - self._used)
```

## 预算的创建时机

### 路径1：每轮对话开始时（turn_context.py:258）

```python
agent.iteration_budget = IterationBudget(agent.max_iterations)
```

每次用户发起新对话轮次，**强制创建全新预算**，上一轮未用完的不累积。上限 = `agent.max_iterations`（默认 90）。

### 路径2：子Agent独立预算（delegate_tool.py:1357）

```python
child = AIAgent(
    max_iterations=max_iterations,   # delegation.max_iterations，默认 50
    iteration_budget=None,           # None → 子Agent自建独立预算
)
```

在 `agent_init.py:405` 中：

```python
agent.iteration_budget = iteration_budget or IterationBudget(max_iterations)
```

`None` 是 falsy → 创建**全新独立的** `IterationBudget(max_iterations)`。

### 关键设计：父子Agent预算是完全独立的

```
父Agent IterationBudget(max=90)  ←→  子Agent IterationBudget(max=50)
        互相独立，互不影响

总迭代次数 = 父Agent消耗 + Σ各子Agent消耗
可以远超父Agent的90上限
```

`iteration_budget` 构造函数参数允许传入共享实例，但当前实现传 `None`，给每个子Agent独立预算池。这个接口保留是为了未来可能的共享预算模式。

## 主循环中的双重检查

**文件**：[`agent/conversation_loop.py`](../../../hermes-agent-main/agent/conversation_loop.py)

### 循环入口条件（第643行）

```python
while (api_call_count < agent.max_iterations       # 硬上限（90）
       and agent.iteration_budget.remaining > 0)    # 可退还预算
      or agent._budget_grace_call:                  # 或最后一次机会
```

三层保护：
1. `api_call_count < agent.max_iterations` —— 不可绕过的绝对上限
2. `iteration_budget.remaining > 0` —— 可退还的资源配额
3. `_budget_grace_call` —— 预算耗尽后允许模型给最后一次回复

### 每轮迭代的消费（第655-668行）

```python
api_call_count += 1

if agent._budget_grace_call:
    agent._budget_grace_call = False   # 一次性flag，用完即弃
elif not agent.iteration_budget.consume():
    # 预算耗尽 → break
    _turn_exit_reason = "budget_exhausted"
    break
```

## 五种退还（Refund）场景

| 位置 | 场景 | 是否联动 `api_call_count -= 1` |
|---|---|---|
| [983行](conversation_loop.py#L983) | Ollama运行时上下文太小，根本没调API | ✅ 联动 |
| [1062行](conversation_loop.py#L1062) | 上下文压缩后重试 | ✅ 联动 |
| [4236行](conversation_loop.py#L4236) | API调用中断后fallback | ✅ 联动 |
| [4251行](conversation_loop.py#L4251) | 超时/中断后重试 | ✅ 联动 |
| [4786行](conversation_loop.py#L4786) | 纯 `execute_code` 工具调用 | ❌ **不联动** |

### 最关键的场景：execute_code 退款（第4781-4786行）

```python
# 如果本轮调用的唯一工具是 execute_code（程序化工具调用），
# 退还预算——这些是廉价RPC调用，不应消耗思考配额
_tc_names = {tc.function.name for tc in assistant_message.tool_calls}
if _tc_names == {"execute_code"}:
    agent.iteration_budget.refund()
```

**这里没有配对的 `api_call_count -= 1`**，这是两者最大的分歧点。

## 两者分歧的三种情况

### 1. Grace Call → `api_call_count > used`

```
预算耗尽时 remaining=0，但 _budget_grace_call=True 让循环多跑一轮:
  api_call_count += 1     →  计数 +1
  consume() 被跳过         →  used 不变
结果: api_call_count = used + 1
```

### 2. execute_code 退款 → `api_call_count > used`

```
初始: api_call_count=5, used=5
第5轮:
  api_call_count += 1    → 6
  consume()              → used=6
  执行 execute_code
  refund()               → used=5  （api_call_count 不变！）
第6轮:
  api_call_count += 1    → 7
  consume()              → used=6

累积偏移: api_call_count = used + 1（每轮纯 execute_code 调用偏移+1）
```

### 3. 压缩重试 → 两者保持同步

```
api_call_count -= 1       # 序号回退
iteration_budget.refund() # 配额退还
→ api_call_count == used
```

## 为什么需要两个计数器而不是一个？

### 1. `api_call_count` 对用户友好

压缩重试时用户看到的是同一个序号（"第5轮重试中"），而不是跳到第6轮又跳回来。序号保持连续稳定。

### 2. `iteration_budget` 表达"思考轮次"

`execute_code` 是程序化RPC，模型通过它做纯计算（循环、数据处理），不应消耗"思考配额"。用户可以 `while True` 做无限计算而不退场。

### 3. 架构上的跨Agent共享能力

`agent_init.py:341` 的接口设计允许传入共享预算：

```python
iteration_budget: "IterationBudget" = None  # None=独立预算；可传入共享实例
```

虽然当前 `delegate_tool.py` 传了 `None`（独立模式），但这个接口允许未来父子Agent共享同一个预算池——父用40次后子只剩50次。`api_call_count` 作为局部变量做不到这一点。

### 4. 防御纵深

即使 `iteration_budget` 因某个bug变成负值，`api_call_count < agent.max_iterations` 仍是不可绕过的硬上限，阻止真正的死循环。

## 完整生命周期示意图

```
用户发起对话 (turn)
  │
  ├─ turn_context.py:258 → 创建全新 IterationBudget(max_iterations)
  │
  └─ conversation_loop.py:643 进入主循环
       │
       ├── while (api_call_count < max_iterations AND remaining > 0) OR grace_call:
       │     │
       │     ├── api_call_count += 1
       │     ├── consume()  [grace_call时跳过]
       │     │
       │     ├── 调用 LLM API
       │     │     │
       │     │     ├── 失败/压缩 → api_call_count -= 1 + refund()  [同步]
       │     │     └── 成功 → 处理工具调用
       │     │           │
       │     │           ├── 纯 execute_code → refund() only  [不同步]
       │     │           └── 其他工具 → 继续循环
       │     │
       │     └── 文本回复 → break
       │
       └── turn_finalizer.py → 记录 budget_used / budget_max
```
